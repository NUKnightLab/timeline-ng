Appearance

Choices about how your timeline looks.

The Timeline NG authoring tool provides a "settings" interface which allows you to make a few choices about how your timeline looks.

More technical users can apply these in a timeline's settings block as well as take a lot more control over a timeline's appearance. See the example app for more information.

Theme

You can choose between "light", "dark", or "auto". "auto" is the default, and follows whatever the reader's own device is set to — so the same timeline appears light to one person and dark to another, matching the rest of what they are reading.

High contrast

Enabling "high contrast" raises every piece of text and every marker to the strictest contrast level in the Web Content Accessibility Guidelines (WCAG AAA), uses heavier type, and thickens the outline that shows which element has keyboard focus.

It applies on top of your other appearance choices rather than replacing them, so it works with any theme and any typeface. Where it and the theme disagree about a color, high contrast wins.

Turning this off does not mean your timeline is inaccessible. The normal appearance already meets WCAG AA, which is the level most accessibility policies require. High contrast goes beyond that, and is worth turning on if you know your audience needs it or if your timeline will be read on projectors or in bright light.

When events bunch together

Events close together in time — many in one decade, or one ancient event and the rest recent — the navigator cannot label all of them without the labels colliding. It shows as many as fit, always including the event you are currently viewing, and leaves the rest as markers on the track. Those markers still work: click one to jump to it. Zooming in (Ctrl or ⌘ + scroll) spreads the events out and the labels reappear.

Typeface

Use the "typeface" menu to choose a headline face and a body face together. These pairings are carried over from the classic TimelineJS, so a timeline moved across should be able to keep the look it had. Note that you'll have to manually set the typeface after importing, as classic TimelineJS did not store typeface settings in the spreadsheet.

The Scripts column in the table below matters if your timeline is not written in the Latin alphabet. Most of these families cover Latin and sometimes Cyrillic and little else. A timeline in a writing system the faces don't cover still displays perfectly well — the text falls back to a standard system font, character by character — but it won't look like the pairing you picked. The settings panel warns you when your timeline's language falls outside the pairing's coverage.

Georgia + Helvetica Neue is the default and the one exception: it uses fonts already on the reader's device, so it downloads nothing and covers every writing system. It is the safe choice rather than the dull one.

Casual users can ignore the "setting value" column. That is provided as a reference for more technical creators.
