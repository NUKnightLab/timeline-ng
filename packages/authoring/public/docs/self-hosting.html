Self-hosting your timeline

Embed a timeline on your own site without using the Atmosphere network.

Overview

The Timeline NG player is a standalone web component you can include on your own web pages. You can export your timeline data as a JSON file from the editor, host it alongside your site, and point the player at it. No server-side code required. You do have to use modern javascript build tools; unlike our other tools, there is currently no support for simply loading Timeline NG with a <script src="..."> tag.

1. Export your data

In the editor, open Publish and click Download JSON. Save the file somewhere in your site's assets — for example timeline.json. See the timeline data format guide if you're writing or generating this JSON by hand instead.

2. Install the player

Install via npm:

npm install @knight-lab/timeline-ng

Then import the styles once in your app entry point:

import '@knight-lab/timeline-ng/styles.css';

3. Add the player to your page

The player ships as a Svelte component. Use loadTimeline to fetch your JSON, then pass the result to SlidePlayer: 

import { SlidePlayer, loadTimeline } from '@knight-lab/timeline-ng';
import '@knight-lab/timeline-ng/styles.css';

const result = await loadTimeline('/path/to/timeline.json');
if (result.ok) {
  // mount SlidePlayer with result.timeline
}

See the project README for complete framework integration examples.

4. Configuration options

If your timeline JSON includes a settings object (see the data format guide), the Timeline NG embed app reads it automatically and applies it. When using SlidePlayer directly, as shown above, you're responsible for reading timeline.settings yourself and passing the matching props — the props below let you override or supply these values manually:

  • language — locale code for date formatting (default: "en")
  • theme — "light", "dark", or "auto" (default)
  • initialIndex — slide number to start on (default: 0)
  • reverseOrder — show events newest-first (default: false)
  • fontPairing — headline and body typefaces (default: "georgia-helvetica"). See Appearance for the list, and serving the fonts below — the player names the faces but does not load them.
  • highContrast — raise text and markers to WCAG AAA (default: false)

SlidePlayer also takes one prop that is not part of the timeline data format, because it is a decision for whoever is embedding rather than for whoever wrote the timeline:

  • navChrome — "standard" (default) or "minimal", which removes the navigator's zoom controls and date axis and reclaims that space.
Before reaching for minimal: when events sit close together the navigator cannot label all of them, and zooming is how a reader gets the missing labels back. On a densely dated timeline, removing the zoom controls takes that away. It is a good fit for a timeline whose events are well spread out, and a poor one otherwise.

5. Serving the fonts

A font pairing sets CSS custom properties naming a headline face and a body face — it does not download anything. That is deliberate: which font service you use, and whether you use one at all, is your decision to make on your own pages. If a named face is not available, the browser falls back through the rest of the pairing's stack, so the timeline still reads correctly; it just won't look like the pairing you chose.

So there are three ways to go:

  • Use the default and serve nothing. georgia-helvetica is built from fonts already present on the reader's device. It needs no downloads and covers every writing system.
  • Load the families yourself. The pairing only asks for a family by name, so any means of providing it works — your own @font-face rules, a font service, whatever you already use. Check the pairing in Appearance for which two families it names.
  • Copy ours. The repository mirrors every pairing's fonts as woff2, with one stylesheet per pairing, under packages/embed/public/fonts/. Copy the <pairing>.css file and the .woff2 files it references into the same directory in your own assets, and link it: 
<link rel="stylesheet" href="/fonts/playfair-faunaone.css">

Those stylesheets keep each family's per-script unicode-range declarations, so a browser downloads only the scripts your timeline's text actually uses — a Cyrillic timeline fetches the Cyrillic slice and never touches the Latin one.

If you redistribute those font files, their licences travel with them. Each family's licence is in packages/embed/public/fonts/LICENSES/.

6. Styling

The player exposes CSS custom properties for theming — colours, typography, spacing, and the navigator's own treatment. Set them on the container or any ancestor element: 

#my-timeline {
  --tl-color-accent: #0066cc;
  --tl-font-heading: 'Georgia', serif;
  --tl-min-height: 300px;
}

Example apps

The timeline-ng repository includes a few small example apps demonstrating different integration patterns:

  • example-svelte5
    Fetches a timeline at runtime (from an AT URI or any URL) with loadTimeline() inside a Svelte component.
  • example-vanilla
    Mounts the player with a plain, hand-written timeline object — no Svelte component authoring required.
  • example-svelte5-json
    Renders the player from a static JSON file bundled with the app — the pattern this guide walks through above.
  • example-custom-theme
    Demonstrates taking more control over the visual style of a timeline and switching between languages.
